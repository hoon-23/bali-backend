# ADR-0003: arm64(Graviton) 인스턴스와 네이티브 arm64 빌드

- 상태: 채택됨
- 결정일: 2026-11-24

## 맥락

같은 사양이면 arm64(Graviton) 인스턴스가 x86보다 싸다. 그런데 CD가 만들던 이미지는 x86(amd64)용이라서,
arm64 서버에서 받으려 하자 `no matching manifest for linux/arm64`로 실패했다. 이미지를 arm64로 빌드해야 했다.

## 결정

운영 서버는 arm64 인스턴스(t4g)를 쓰고, CD는 GitHub의 arm64 러너(`ubuntu-24.04-arm`)에서 이미지를 네이티브로
빌드한다. 저장소가 공개라서 이 러너는 무료다.

## 검토한 대안

- x86 인스턴스(t3.medium, 월 약 $38 대 t4g.medium 약 $30): 이미지를 다시 빌드할 필요가 없지만 약 25% 비싸다.
- x86 러너에서 buildx로 에뮬레이션 빌드: Gradle 빌드가 에뮬레이션 위에서 돌아 느릴 것으로 보고 택하지 않았다(측정하지 않은 추정).

## 결과

- 얻는 것: 인스턴스 요금이 낮고, 이미지가 서버와 같은 아키텍처라 서버에서 호환 문제가 없다.
- 감수하는 것:
  - 테스트(CI)는 x86 러너에서 돌고 이미지는 arm64로 빌드된다. JVM 앱이라 차이가 작을 것으로 보지만 보장은 아니다.
  - 배포된 이미지는 처음부터 arm64 서버에서 실제로 기동해 검증했다.
