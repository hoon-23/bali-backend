# ADR-0008: 레벨·경험치는 저장하지 않고 조회 때 계산

- 상태: 채택됨
- 결정일: 2026-10-02
- 소급 작성: 2026-11-24

## 맥락

사용자에게 레벨과 경험치(EXP)를 보여 주기로 했다. EXP는 인정된 세션의 날짜별 이력(세션 수와 연속 운동일)만으로 정해진다.
기록 없이 세션을 많이 만들거나 종료만 눌러 EXP를 올리는 것은 막아야 한다.

## 결정

EXP와 레벨을 저장하지 않고 조회할 때 세션 이력에서 계산한다. 레벨 테이블, enum, EXP 컬럼을 두지 않는다.
레벨 곡선은 공식(`1000 × 1.05^(레벨-1)`)이라 레벨 상한도 없다.

## 검토한 대안

- EXP 컬럼이나 레벨 테이블에 저장: 이력만으로 값이 정해져 별도 저장이 필요 없고, 저장하면 규칙을 바꿀 때마다 마이그레이션이 필요하며 세션 삭제와 상태 변경도 직접 반영해야 한다.
- 같은 날 여러 세션의 평균 EXP: 세션을 3개 해도 1회분이라 부당해서 기각하고, 하루 인정 세션 수 한도로 처리했다.
- 곡선 증가율 ×1.10: 후반이 너무 느려(레벨 20까지 약 3.7년) ×1.05로 정했다.

## 결과

- 얻는 것: 스키마 변경이 없고, 규칙을 바꿔도 마이그레이션이 필요 없다. 세션 삭제나 상태 변경이 자동으로 반영된다.
- 감수하는 것: **규칙이 바뀌면 과거 레벨도 함께 바뀐다.** 새 규칙은 기준일 이후 세션에만 엄격하게 적용하고 소급하지 않는 방식으로 완화했다(소급하면 실제 계정 기준으로 인정 세션이 199개에서 58개로 줄어 레벨이 크게 내려간다).
