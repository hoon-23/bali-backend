# ADR-0009: Spring Batch를 쓰지 않고 순수 Kotlin 러너로 배치 구현

- 상태: 채택됨
- 결정일: 2026-08-07
- 소급 작성: 2026-11-24

## 맥락

초기 설계는 주간 분석 배치를 Spring Batch로 만들고, 사용자별 처리에서 실패한 사용자만 건너뛰는 skip 정책을 쓰기로 했다.
이후 설계가 단순해졌다. 배치는 사용자를 순회하며 집계, 규칙 평가, 저장을 하는 작업이고, 스케줄링과 재시도는 외부(로컬은 Airflow, 운영은 cron)가 맡는다.

## 결정

`bali-batch`는 웹 서버 없이 실행하고 종료 코드만 반환하는 순수 Kotlin 러너다. 러너가 사용자 순회, 실패 격리(try/catch), 저장을 직접 조율한다.
실행할 작업은 첫 번째 명령줄 인자로 고른다.

## 검토한 대안

- Spring Batch: 사용자별 실패 격리가 도입 이유였는데 설계가 단순해지면서 그 이유가 사라졌다.

## 결과

- 얻는 것: 한 사용자가 실패해도 나머지에는 영향이 없다. 같은 기간을 다시 실행하면 전체를 재계산해 결과가 같은(멱등) 구조라, 실패하면 다시 실행하면 된다. 구성이 단순하고 컨테이너로 바로 실행된다.
- 감수하는 것: Spring Batch의 작업 이력, 재시작 같은 기능은 쓰지 않는다. 유저 순회와 같은 조율 코드는 러너에 직접 둔다. 별도의 서비스 계층은 만들지 않았고, 필요해지면 추가한다.
