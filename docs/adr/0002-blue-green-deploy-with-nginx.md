# ADR-0002: nginx 블루/그린으로 무중단 배포

- 상태: 채택됨
- 결정일: 2026-11-24

## 맥락

서버가 한 대라 컨테이너를 재시작하는 방식으로 배포하면 앱 기동(약 65~75초)과 헬스체크 동안 1~2분 중단된다.
이전 구조(ECS)는 새 태스크가 뜬 뒤 옛 태스크를 내리는 롤링 방식이라 중단이 없었고, 그 성질을 유지하고 싶었다.
유료 요금제를 제공할 때 배포 때마다 중단되면 결제 사용자에게 바로 불편이 된다.

## 결정

서버의 nginx가 요청을 받고, API 컨테이너를 blue/green 두 개로 번갈아 띄운다. 새 버전을 반대 색상으로 띄워
헬스체크가 통과하면 nginx가 가리키는 대상을 바꾸고, 잠시 뒤 이전 버전을 내린다. 헬스체크가 실패하면 전환하지 않고
기존 버전을 유지한다.

## 검토한 대안

- 컨테이너 단순 재시작(t4g.small, 월 약 $20~23): 가장 싸고 단순하지만 배포마다 1~2분 중단된다.

## 결과

- 얻는 것: 전환 중 요청 129건이 모두 200이었다. 헬스체크 실패 시 기존 버전이 그대로 유지된다.
- 감수하는 것:
  - 전환 순간 JVM이 두 개 떠서 메모리가 약 768MB 더 필요하다. 그래서 인스턴스를 t4g.medium으로 올렸고 월 약 $15가 더 든다.
  - 정상 기동한 뒤 발견되는 버그는 자동으로 되돌려지지 않는다. 이전 커밋을 지정해 다시 배포해서 롤백한다.
  - 두 버전이 잠시 같은 DB를 쓰므로, 컬럼 삭제나 이름 변경처럼 이전 버전을 깨는 마이그레이션은 두 번에 나눠 배포한다.
  - 서버가 한 대인 점은 그대로라, 서버 자체의 장애는 막지 못한다.
