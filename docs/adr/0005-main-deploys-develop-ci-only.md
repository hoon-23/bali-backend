# ADR-0005: 브랜치 전략: main 병합이 운영 배포, develop은 CI만

- 상태: 채택됨
- 결정일: 2026-11-24

## 맥락

이전에는 `develop`에 병합하면 곧바로 배포됐다. 그 환경은 dev라고 불렸지만 앱 사용자가 쓰는 유일한 환경이라 사실상 운영이었다.
단일 EC2로 옮기면 배포 때마다 서버의 컨테이너가 교체되므로, 병합할 때마다 사용자에게 반영되는 구조는 위험하다.

## 결정

`develop` 병합은 CI(테스트)만 실행한다. 운영 배포는 `develop`을 `main`에 병합할 때만 하고, 테스트가 통과해야 이미지를 빌드해 배포한다.
롤백은 CD를 수동 실행하며 이전 커밋을 지정한다.

## 검토한 대안

- `develop` 병합마다 배포(기존 방식): 단순하지만 검토 중인 변경이 곧바로 사용자에게 간다.
- 별도 dev 환경을 상시 운영: 서버를 하나 더 두어야 해서 이번 이전의 비용 목표와 맞지 않는다. 필요할 때만 띄우는 dev 환경은 후속 과제로 남겼다.

## 결과

- 얻는 것: 배포가 `main` 병합이라는 의도적인 행동이 되고, 배포 횟수가 줄어 서버 교체 영향도 줄어든다.
- 감수하는 것: 변경이 운영에 반영되려면 `main`으로 가는 PR을 한 번 더 병합해야 한다. 문서 사이트도 `main` 기준으로 게시된다.
