# ADR-0004: 배치 실행을 서버의 호스트 cron으로 통일

- 상태: 채택됨
- 결정일: 2026-11-24

## 맥락

배치(`bali-batch`)는 하루 최대 몇 분 도는 작업 7개다. 처음 설계는 로컬 Airflow를 AWS에 그대로 올리는 방식을 상시
비용 때문에 버리고 EventBridge Scheduler + ECS RunTask로 바꿨다
([배치 AWS 배포 설계](../specs/2026-09-14-batch-aws-scheduling-design.md)). 운영을 단일 EC2로 옮기면
ECS 클러스터가 배치만을 위해 남게 된다.

## 결정

서버의 cron이 한국 시간 기준으로 `bali-batch` 컨테이너를 실행한다(작업 한 개당 컨테이너 하나, 끝나면 종료).
작업이 0이 아닌 종료 코드로 끝나면 알림을 보낸다. 로컬 개발에서는 Airflow를 그대로 쓴다.

## 검토한 대안

- EventBridge + ECS RunTask 유지: 서버리스라 서버와 분리되지만, 배치 하나를 위해 ECS와 네트워크 구성을 유지해야 하고 실행당 비용이 든다.
- Airflow 상시 운영: 이전 설계에서 이미 기각했다(스케줄러가 상시 가동되는 비용 구조).

## 결과

- 얻는 것: 추가 비용이 없고 구성요소가 줄었다. 이전 설계에서 시간 오프셋으로 근사하던 작업 순서(분석 → 푸시)도 그대로 유지된다.
- 감수하는 것:
  - API와 같은 서버에서 도므로 메모리를 나눠 쓴다. 배치 컨테이너는 메모리 상한을 두고, 서버에 스왑을 둬서 완충한다.
  - 서버가 내려가 있으면 그 시간대 작업은 실행되지 않고, 재실행은 수동이다.
  - 이전 중 두 시스템이 동시에 돌아 푸시가 중복 발송되지 않도록, 전환 시점에 한쪽을 끄고 한쪽을 켜는 플래그를 둔다.
