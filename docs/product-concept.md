# 제품 개요 (Swayt)

운동 기록을 템플릿 기반으로 계획하고 세션으로 기록하면, 서버가 주간/월간 통계와 규칙 기반
인사이트를 만들어 주는 모바일 앱의 백엔드입니다. 구현 현황은 코드와 `docs/specs/`가 기준이고,
이 문서는 제품이 무엇이고 왜 이런 모양인지를 설명합니다. 모바일 클라이언트는 `bali-frontend`
(Expo, iOS 우선)가 맡습니다.

## 1. 배경

3년간 애플 기본 메모 앱에 적어 온 운동 기록을 정형화해 통계로 분석하려는 데서 출발했습니다.
처음엔 1인용이었지만 멀티유저 구조로 넓혔고, TestFlight 배포를 전제로 한 실제 모바일 앱을
목표로 합니다. 앱 이름은 Swayt(sway + sweat)입니다.

## 2. 핵심 컨셉

템플릿(루틴)으로 계획하고, 세션으로 실제 수행값을 기록하면, 배치가 주간/월간으로 집계해
인사이트 문장을 만들어 줍니다. 인사이트는 통계와 if/else 규칙으로 만들며 LLM은 쓰지 않습니다.
LLM 연동은 로드맵에서 제외했습니다.

## 3. 도메인

- **User**: Google/Naver/Kakao/Apple 소셜 로그인 후 자체 JWT를 발급합니다. 닉네임(자동 생성),
  주간 목표 횟수, 연속 운동일, 레벨/경험치, 플랜(FREE/PRO)을 가집니다. 탈퇴하면 PII를 익명화해
  파기합니다.
- **Exercise(종목)**: GLOBAL 시드와 사용자가 만든 PERSONAL로 나뉩니다. 근육군과 장비로 분류하고
  `type`(STRENGTH/CARDIO)에 따라 입력 필드가 갈립니다. 새 종목을 입력하면 pg_trgm 유사도로
  기존 종목을 제안합니다. 과거 기록에 오타성 변형이 많아서 생긴 기능이며, 관리자가 사후에
  정규화하는 기능은 신뢰도 문제로 두지 않았습니다. PERSONAL 종목 삭제는 소프트 삭제라서 과거
  기록은 그대로 남습니다.
- **WorkoutTemplate**: PUSH/PULL/LEGS/STRENGTH 카테고리의 재사용 가능한 루틴입니다. 종목별
  목표값(세트/횟수/무게 또는 시간/페이스)을 가집니다.
- **WorkoutSession**: 날짜별 실제 기록입니다. 템플릿을 복사해 시작하지만 이후엔 독립적이라
  종목을 자유롭게 추가/변경/삭제할 수 있고, 목표값이 없는 즉흥 종목도 기록할 수 있습니다.
  상태는 SCHEDULED/IN_PROGRESS/COMPLETED/ABANDONED이며, 세트별 시작/종료 타이머와 운동 후
  체감 난이도(RPE 1~10)를 저장합니다. 방치된 세션은 배치가 ABANDONED로 정리합니다.
- **Analysis**: 주간/월간 분석입니다. 총 운동시간, 종목별/근육군별 볼륨, 유산소 총시간, 완료율,
  운동 빈도(횟수)와 강도(세션당 평균)의 전 기간 대비 증감률과 인사이트 문장을 담습니다.
  상태는 SUCCESS/FAILED/NO_ACTIVITY입니다. 일간 분석과 전체 기간 누적 통계는 조회 시점에 계산합니다.
- **Notification**: 주간/월간 요약, 루틴 리마인더, 미활동 알림을 Expo 푸시로 보내고 알림함에
  쌓습니다. 앱 아이콘 뱃지는 미읽음 수입니다. 사용자별 설정으로 종류마다 끌 수 있습니다.

## 4. 주요 규칙

- **레벨/경험치**: 저장하지 않고 조회 때 세션 이력에서 계산합니다. 기록이 있는 완료 세션당
  100 XP, 하루 최대 2세션을 인정하고, 연속 운동일이면 1.2배를 줍니다. 상세 규칙과 예시는
  `docs/specs/2026-10-02-user-level-xp-design.md`를 봅니다.
- **기록 없는 세션**: 기록이 없는 세션은 XP와 운동 통계에서 제외합니다(2026-10-02 이후, 소급 없음).
- **무료 플랜 한도**: 루틴 수, 직접 만든 운동 수, 월간 인사이트를 제한할 수 있지만 기본은
  꺼져 있습니다(`limits-enabled=false`). 인앱 결제와 실제 사용 데이터가 준비된 뒤에 켭니다.
- **클라이언트 우선 처리**: 서버 호출을 줄이기 위해 가능한 계산은 클라이언트에서 하고 한 번에
  동기화합니다. 예를 들어 휴식 시간 계산과 타이머, 잊힌 타이머 알림은 클라이언트 몫입니다.

## 5. 범위 밖

- 관리자에 의한 사후 종목 정규화
- LLM/Claude API 기반 인사이트와 자연어 질의 API (2026-09-10 스코프 아웃)
- 3년치 개인 기록 이관은 정식 기능이 아니라 본인 계정 시딩용 1회성 스크립트
- 보류: PR(개인 기록) 감지, 템플릿 공유(다른 유저 템플릿 복사)

## 6. 개인정보

로그인이 있어 개인정보보호법(PIPA) 항목을 점검했고 대부분 처리했습니다. 탈퇴 시 PII 익명화,
개인정보처리방침 공개(`GET /api/v1/legal/privacy-policy`, 정적 사본은 GitHub Pages), 국외 이전
고지(Google/Apple)를 반영했습니다. 운동 기록은 민감정보가 아니라고 판단했으며 법률 자문이 아닌
실무 관행 기준입니다. 심박수나 수면 같은 생체 지표를 추가하면 다시 검토합니다. 남은 것은
클라이언트의 동의 UI입니다.

네이버는 토큰이 우리 앱에 발급된 것인지 검증할 API가 없어 서버 쪽 알려진 보안 리스크가
남아 있습니다. 해결하려면 서버가 authorization code를 직접 교환하는 방식으로 바꿔야 합니다.

## 7. 운영 환경

AWS dev 환경(CloudFront → ALB → ECS Fargate → RDS)이 Terraform으로 구성돼 있고, develop에
푸시하면 CD가 배포합니다. 배치는 EventBridge Scheduler가 트리거합니다. 로컬에서는 Airflow가
같은 역할을 합니다. 비용 때문에 ECS `desired_count`를 0으로 내려 두는 일이 있으니, 서버가 503이면
장애보다 먼저 이 값을 확인합니다. 절차는 `docs/runbooks/`를 봅니다.
