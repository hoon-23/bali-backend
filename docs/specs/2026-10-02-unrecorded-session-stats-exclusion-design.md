# 기록 없는 세션을 운동 통계에서 제외

2026-10-02. bali-backend 변경. 요청 출처: bali-frontend 세션(사용자 결정이라고 전달), 사용자 확인 완료(소급 적용 안 함).

## 문제
세트·횟수를 기록하지 않고 "완료로 표시"만 한 뒤 운동을 종료한 세션이 XP에서는 빠지지만(2026-10-02 반영) 운동 통계에는 그대로 잡힌다. 프론트 로컬 테스트에서 0세트 세션 하나로 총 운동일이 299 → 300, 이번 주 운동일이 1 → 2가 됐다.

## 결정 사항
- XP 인정 조건과 **같은 기준, 같은 기준일(세션 date 2026-10-02 이후)**을 통계에도 적용한다. 소급하지 않는다.
- 기준일 이전 세션은 각 통계의 **지금 동작을 그대로 유지**한다. 로컬 실제 계정은 세션이 있는 날 300일 중 101일이 완료 로그가 없고(옛 운동 일지를 옮긴 상세 없는 세션), 완료 로그 964개 중 756개가 세트·횟수가 없어서 소급하면 총 운동일과 운동시간이 크게 줄어든다.
- 응답 필드는 바뀌지 않고 집계 조건만 바뀐다. 프론트 변경은 없다.
- 기록 탭의 세션 목록/상세는 그대로 보여준다(조회 API는 변경 없음).

## 기준
- **수행 기록이 있는 로그**: 근력은 `actualSets > 0`이고 `actualReps > 0`, 유산소는 `actualDurationSeconds > 0` (기존 `SessionLog.hasPerformanceRecord()`).
- **집계 대상 로그**: `completed=true`이고, 세션 date가 기준일 이후면 수행 기록도 있어야 한다. 기준일 이전이면 `completed=true`만 본다.
- **집계 대상 세션**: 집계 대상 로그가 1개 이상인 세션. 다만 기준일 이전 날짜는 통계마다 지금 쓰는 기준을 유지한다(아래 표).

기준일 이후에 완료 체크만 하고 기록이 없는 로그는 통계에서 **완료하지 않은 로그와 같게** 취급한다.

## 통계별 적용
| 통계 | 기준일 이전(현행 유지) | 기준일 이후 |
|---|---|---|
| 누적 총 운동일 (`/analysis/lifetime`) | 세션이 하나라도 있는 날 | 집계 대상 세션이 있는 날 |
| 누적 총 운동시간, 일별 운동시간/완료 세트 (`/analysis/daily`) | 완료 로그 기준 | 집계 대상 로그 기준 |
| 일별 `sessionsCount` | 그날의 세션 수 | 그날의 집계 대상 세션 수. 0이면 그 날짜는 결과에서 빠진다 |
| 이번 주 운동일 (`/users/me`의 `weeklyWorkoutDays`) | 완료 로그가 있는 날 | 집계 대상 로그가 있는 날 |
| 주간/월간 요약(`/current` 포함): 운동 시간, 볼륨, 근육군별 세트, 맨몸 반복수, 유산소 시간 | 완료 로그 기준 | 집계 대상 로그 기준 |
| 주간/월간 `sessionCount`와 빈도 인사이트 | 완료 로그가 있는 세션 | 집계 대상 세션 |
| 완료율 | 완료 로그 수 ÷ 전체 로그 수(중단 세션 로그 제외) | 분자를 집계 대상 로그 수로 바꾼다. 분모는 그대로 |
| `/current`의 `completedSessionsCount` | status COMPLETED인 세션 수 | COMPLETED이고 집계 대상 세션인 것만 |
| 미실행(이탈) 알림의 마지막 운동일 | 완료 로그가 있는 가장 최근 날 | 집계 대상 로그가 있는 가장 최근 날 |
| XP/레벨 | 변경 없음 (이미 같은 기준) | 변경 없음 |

- 완료율의 분모를 그대로 두는 이유: 계획하고 하지 않은 세션이 완료율을 낮추는 지금 의미를 유지하기 위해서다. 0세트로 종료한 세션은 건너뛴 세션과 같이 완료율을 낮춘다.
- 연속일: 백엔드에는 XP 연속 보너스 외에 별도 연속일 API가 없다. XP 쪽은 이미 같은 기준이고, 프론트가 일별 집계로 연속일을 계산한다면 위 일별 변경으로 함께 맞춰진다.

## 구현
- 기준을 한 곳에 모은다: core `session` 패키지에 기준일 상수와 `SessionLog.countsAsWorkout(sessionDate)`, `WorkoutSession.hasCountedLog()`를 두고, `UserLevel.STRICT_QUALIFICATION_FROM`과 `isXpQualified()`는 이것을 쓰도록 바꾼다(동작 변화 없음).
- core: `PeriodStatsCalculator`와 `DailyStatsCalculator`가 `completed` 대신 위 기준을 쓴다. 일별은 기준일 이후 날짜에 집계 대상 세션이 없으면 그 날짜를 결과에서 뺀다.
- infra: `findActiveDates`, `findLastActiveDate` 쿼리에 XP 집계 쿼리와 같은 조건(기준일 이후는 수행 기록 필요)을 추가하고 기준일을 인자로 받는다.
- api: `/current`의 `completedSessionsCount` 계산을 바꾼다.
- 이미 저장된 주간/월간 분석은 다시 계산하지 않는다. 기준일이 걸친 주(9/28 주)와 10월 분석부터 새 기준으로 저장된다.

## 테스트
- core: 기준일 전후의 집계 대상 로그/세션 판정, 주간/월간 요약(0세트 완료 로그가 시간·세트·세션 수에서 빠지고 완료율을 낮추는지), 일별(기준일 이후 0세트만 있는 날짜가 빠지고, 기준일 이전 로그 없는 세션 날짜는 남는지).
- 어댑터: `findActiveDates`, `findLastActiveDate`의 기준일 전후.
- 컨트롤러: `/users/me`의 `weeklyWorkoutDays`, `/analysis/lifetime`, `/current`의 `completedSessionsCount`.
- 로컬에서 앱을 실행해 실제 계정의 총 운동일이 그대로인지(소급 없음)와 0세트 세션이 통계에 잡히지 않는지 확인한 뒤 push 승인을 받는다.
